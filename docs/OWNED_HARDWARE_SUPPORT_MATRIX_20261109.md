# 当前硬件支持状态矩阵

记录日期：2026-11-09。

本文整理本轮活跃支持对象：开发板、摇杆、DHT22、WS2812 灯环，以及 HC-SR04、电位器、MPU6050、DS1307 四个无实物的通用参考器件。后者用于验证“常用硬件扩展支持”，不能标记为实物可用。屏幕、舵机、麦克风、扬声器和 USB 摄像头仍是已购硬件，但涉及显示、执行器或音频/USB 专项能力，暂不混入本矩阵。

## 状态口径

以下状态可以并存，不能互相替代：

| 状态 | 含义 | 证据要求 |
|---|---|---|
| `registered` | 已有知识卡或库存记录 | 知识卡、库存文件 |
| `user_reported_ok` | 用户口头或人工试用反馈可用 | 用户陈述；只代表用户观察 |
| `compile_verified` | 某个具体工程已通过 PlatformIO 编译 | 构建记录、exit code |
| `export_verified` | 已导出可由 VS Code/Wokwi 打开的工程 | 导出 manifest |
| `simulation_verified` | 自动化仿真场景有确定性通过判定 | scenario、日志、截图/串口等证据 |
| `physical_verified` | 实物电气和功能验证通过 | 实测记录、照片/仪表证据 |
| `known_issue` | 已确认的兼容或生成问题 | 失败证据与对照实验 |

用户反馈“没什么问题”不能自动升级为 `simulation_verified` 或 `physical_verified`。反之，某个复杂组合失败也不能直接归因于单个器件。

## 优先顺序

1. **WS2812 最小视觉基线**：成本低、证据直观，可以首先确认“只亮一颗”是生成问题还是仿真/驱动观测问题。
2. **DHT22 实物边界确认**：仿真基线已收敛为本地驱动包和无外接上拉三线；下一步只补实物模块针序、板载上拉和供电验证，不再设计驱动变体选择机制。
3. **MPU6050 与 DS1307 最小仿真基线**：拆开验证 I²C 传感器和 RTC 的通用参考支持，不复用复杂组合工程作为结论。
4. **HC-SR04 与电位器最小行为场景**：分别改变距离/位置并断言输出；电位器先用串口，避免第三方舵机库缺包影响。二者同样按无实物仿真参考器件处理。
5. **摇杆回归**：作为已有较稳对象，用自动化 controls 验证中心、四方向、按键和消抖，再考虑升级状态。

## 必须先确认的信息

- HC-SR04、电位器、MPU6050、DS1307 已确认无实物；后续只作为常用 Wokwi 参考器件扩展，不安排实物测试。
- 若未来把 MPU6050 或 DS1307 升级为实物支持，需要补充具体模块型号、电源、接线端子和上拉情况。
- DHT22 红板实际针序与是否已有板载上拉；这不影响当前 ESP32-S3/Wokwi 三线仿真基线，但影响实物结论。
- WS2812 用户观察到“只有一颗亮”的工程入口、运行方式，以及当时需求是否本来就只要求一颗亮。
