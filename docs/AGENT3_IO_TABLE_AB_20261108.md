# Agent3 完整 IO 接线表：前后各两次真实对照

日期：2026-11-08（原始运行记录使用 UTC）。本报告接续 [程序 GPIO 表与 Agent2 测试](GPIO_MAP_20261108.md)。

## 结论

完整接线表已接入 Agent3，四次运行都产出经过现有静态检查的计划；工程源码、设计、修订及身份哈希未改变。没有执行仿真，因此不声称计划已在模拟器中运行成功，更不声称功能验收通过。

本组未显示效率提升。加入前平均 127,774 reported tokens，加入后平均 144,365，增加 16,591（约 13.0%）。加入后的第二次发生两次自动修正；其余三次无格式/契约修正。只测一份工程、每组两次，不能据此判定完整接线表普遍增大成本或导致错误。

保留完整表有明确的架构意义：把程序确定的接线关系提供给规划器，减少自行推导的需要。但它不会自动解决需求理解、场景组织、判据正确性和 JSON 契约问题。

## 只改变什么

加入前已经存在 `io_map.inputs/outputs`，包含串口、摇杆控制与可读取端点；本次新增 `io_map.wiring`，装入**完整程序生成接线报告**，不是删减后的概要。

报告包括全部已用 GPIO、板端点别名、外设端点及信号、设计常量、板级限制提示、未知端点、解析问题、来源、版本及哈希。当前工程含 GPIO1/HORZ、GPIO2/VERT、GPIO4/SEL 和 GPIO43/44 串口。接线报告由当前工程快照重新生成，不依赖 Agent2 抄写，也不信任旧表缓存。

生产改动集中在 `LangChain/hardware_claw/stages/verification_context.py`。原提示词、JSON 模板、契约、模型配置、操作权限和预算均未修改。现有共享 `io_map` 自动把完整表传入场景规划、每个时间线以及修正请求。需求提取阶段仍只接收需求原文和本轮范围，不需要接线表。

操作名称只能来自 `inputs/outputs`，不能把 `wiring`、GPIO 数字或表格元数据当作新的操作通道。表格不能证明 ADC 数值、电压、固件模式、上拉配置或精确时序。

### 人工审阅发现的实质问题

四份最终场景与时间线均已阅读。它们覆盖两轴变化、按键按放、持续串口输出等核心可观测行为，但静态检查只检查结构与工具参数，不解决以下语义问题：

- **加入前 1，T8**：把“工程中说明实物限制”扩展成“启动串口包含说明文字”，并在后续已经清除过的缓冲区继续期待一次性启动文本。用户要求的是工程说明，固件没有义务打印这段声明，可能误判失败。
- **加入前 1，T7**：单次 TX 数字读数被描述成可判断是否存在电平翻转，这超出单点读数的证据能力；GPIO1 单点数字读数也不能独立证明连线存在。
- **加入后 1，T1**：引入“中位约 2048”，同时又声明 ADC 转换/绝对数值没有完整依据；接线表只说明 GPIO1 接 HORZ，不能补足 ADC 转换关系。另一处将低有效方向也概括成无法用数字脚验证，过于保守；数字高低可以观测，但内部上拉配置不能据此独立证明。
- **加入后 1，T1/T3**：分别设定 60 秒/30 秒场景，但最后一次观察在 12 秒/10 秒；转换结果会保留无新采证的 48 秒/20 秒尾部等待。接线表没有自动减少这些无效等待。
- **加入后 2，T6**：期待 README 所述“启动空行”，而 README 没有该要求，源码也没有相应空行。这仍是缺少依据的附加判据。
- **前后均存在**：在模拟输入脚上追加数字读数，并称其仅用于“辅助记录”或“确认连线”。它们没有被直接当作 ADC 数值，但对当前需求的判别价值很低。按键 GPIO4 的按下低/释放高对照有明确用途；两者不应混为一谈。

因此目前不能声称加入完整表提高了计划质量。它补充了确定的结构信息；后续更需要通用的判据依据检查、观察价值检查、无采证等待处理与明确的精确时序缺口。此次为保持对照，只记录问题，没有修改提示词、放宽检查或手工改写生成计划。
