# 测试阶段运行预算

统一配置：`LangChain/hardware_claw/limits.py`，配置版本 `development_v1`。修改后重启服务；这些是上限，不是每次运行需要用满的目标。所有工程使用同一套规则。

| 项目 | 工程模式 | 查询模式 |
| --- | --- | --- |
| 单次模型输出 | 16384 tokens | 4096 tokens |
| 每轮模型调用 | 60 | 16 |
| 每轮工具调用 | 160 | 48 |
| 图执行步数 | 512 | 128 |
| 每轮总时限 | 3600秒 | 600秒 |

- 单次 API 请求120秒，不自动重试；保留最近6轮完整问答，输入最多32000字符。
- 单次编译900秒；每轮最多10次仿真，每次30秒模拟时间、180秒宿主墙钟、4MiB日志。
- 工程最多128文件，单文件256KiB，总计2MiB；设计最多64元件、256连线、64依赖；补丁最多128000字符。
- 不另设整轮累计token硬上限；调用次数与时间仍受控。路径隔离、版本检查、凭据隔离、取消和进程清理保持有效。
- 不固定限制为两轮修复；在预算内根据新证据迭代，反复没有进展时应停止并说明原因。

工程运行记录位于 `workspace/<project_id>/.hwclaw/runs/<run_id>/run.json`。summary保存预算快照、实际时限、模型响应数、工具请求/结果数、总耗时、提供方返回的输入/输出token；response_metrics逐条记录finish_reason、模型名、token、无效工具调用数和从本轮开始计算的累计时间。缺失usage时不推测token；异常终止时统计可能不完整。

后续按多种任务的成功、失败、截断、耗时及成本分布调整，不能只为某个例子放宽或收紧。提高输出上限可以降低长文件截断概率，但未实现无效工具参数自动恢复；提供方是否接受16384以及原失败任务是否完成，仍需真实运行验证。仿真日志不等于功能验收通过。
