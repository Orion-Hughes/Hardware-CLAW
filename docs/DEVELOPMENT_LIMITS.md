# 测试阶段运行预算

统一配置：`LangChain/hardware_claw/limits.py`，配置版本 `cost_bounded_v3`。按用户要求，工程模式每轮累计token预算由20万提高至50万；查询预算和其他限制保持不变。修改后重启服务；这些是上限，不是每次运行需要用满的目标。所有工程使用同一套规则。

| 项目 | 工程模式 | 查询模式 |
| --- | --- | --- |
| 单次模型输出 | 16384 tokens | 4096 tokens |
| 每轮累计输入+输出token预算 | 500000 | 80000 |
| 每轮模型调用 | 20 | 8 |
| 每轮工具调用 | 160 | 48 |
| 图执行步数 | 512 | 128 |
| 每轮总时限 | 3600秒 | 600秒 |

- 单次 API 请求120秒，不自动重试；保留最近6轮完整问答，输入最多32000字符。
- 单次编译900秒；每轮最多10次仿真，每次30秒模拟时间、180秒宿主墙钟、4MiB日志。
- 工程最多128文件，单文件256KiB，总计2MiB；设计最多64元件、256连线、64依赖；补丁最多128000字符。
- `TokenBudgetMiddleware`在动态Context Provider及MessageViewMiddleware之后、模型发送之前执行；累计计入每次实际模型视图的输入、工具结果和输出，缓存命中也计入预算。
- 请求前以聊天协议消息及工具Schema的UTF-8字节数加4096余量保守预估输入，并预留输出额度；不把LangChain本地usage/追踪信息/重复tool_calls算作模型输入。剩余额度不足时不发请求。单次输出可使用16384，但会按剩余总预算缩减。回复后用有效usage校正；usage缺失或请求异常则保留预留额度，不按零处理。
- 这是本地预算阻断，不是提供方计费tokenizer或人民币账单硬上限；估算可能提前阻断，不能承诺服务端计数绝不超过本地估算。上限不会自动增加。每条用户消息开始新一轮预算，不是整个聊天或账户累计上限。
- 不固定限制为两轮修复；在预算内根据新证据迭代，反复没有进展时应停止并说明原因。

工程运行记录位于 `workspace/<project_id>/.hwclaw/runs/<run_id>/run.json`。summary保存预算快照、实际时限、模型响应数、工具请求/结果数、总耗时、提供方返回的输入/输出token；response_metrics逐条记录finish_reason、模型名、token、无效工具调用数和从本轮开始计算的累计时间。缺失usage时不推测token；异常终止时统计可能不完整。

后续按多种任务的成功、失败、截断、耗时及成本分布调整，不能只为某个例子放宽或收紧。提高输出上限可以降低长文件截断概率，但未实现无效工具参数自动恢复；提供方是否接受16384以及原失败任务是否完成，仍需真实运行验证。仿真日志不等于功能验收通过。
