# 2026-11-09 版本检查点

基线提交：`95a7bcd0d4c34d2f793e23e29dadd24a57c7f1d2`。

本检查点记录当前分支相对该基线的主要变化，用于区分“实现已落地”和“仍待验证”的能力。

## 相对上一版的变化

1. **Workspace 命名与清理规则**
   - 新工程 ID 统一为 `tester-hardware-task-random6`，测试者来自环境变量或本地忽略文件。
   - 旧工程不迁移；重复或已被取代的工程先移动到 `temp/workspace-retired-*`，不直接永久删除。

2. **程序生成 GPIO 接线表**
   - 由 `diagram.json` 与上游板卡引脚定义派生 JSON/Markdown 接线表。
   - 表格不由模型编写，不产生新的工程修订，也不证明电气或固件行为正确。
   - `get_project`、`check_project_files` 返回完整表；普通写入只返回引用，减少上下文重复。
   - Agent3 的 `wiring` 上下文包含完整接线表，场景规划和时间线可复用同一份连接事实。

3. **宿主管理的本地驱动包**
   - 新增 `local_bundle` 驱动解析机制，由宿主在编译和导出快照中注入。
   - DHT22 仅暴露本地维护的 DHTesp 1.19 驱动包，不再把上游同名库作为可选依赖。
   - 模型不能生成、修改或提交本地驱动包文件；相关路径由基础检查拦截。

4. **Wokwi 属性硬契约**
   - `diagram.json`、`platformio.ini`、`wokwi.toml` 变为宿主受控文件，模型不能直接写入或 patch。
   - 硬件快照中的 `simulation.proposed_attrs` 必须完整落到 diagram，缺失、多余或值不一致都会报 `SIMULATION_ATTRS_MISMATCH`。
   - 固件中的同类运行参数必须使用同一值，例如可寻址 LED 数量、分辨率、地址或量程，不得依赖 Wokwi/驱动默认值。
   - 该修复针对通用配置契约，不是 WS2812 单工程特例。

5. **外设刷新与文档状态**
   - 通用固件技能要求外设按状态变化或固定周期刷新，禁止高速循环中无条件提交显示帧或像素帧。
   - 新增活跃硬件支持矩阵，把注册、用户反馈、编译、导出、仿真和实物验证分层记录。
