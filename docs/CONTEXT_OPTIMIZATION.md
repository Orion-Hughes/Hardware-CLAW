# 通用上下文优化：第一阶段

历史设计记录：本文的 get_hardware_info 分组接口已由 search_hardware/read_hardware 替代；不代表当前存在一套独立上下文 Provider。当前资料与阶段流程见[文档导航](README.md)。

本阶段只调整工具接口返回和读取粒度，不压缩历史消息，不更改生成工程、不改变验证结论。

## 已实现

- 设计保存、脚手架、文件写入和补丁返回版本、文件清单及验证状态，不重复需求与设计全文；完整状态仍保存为不可变修订，可用 get_project 读取。
- compile_project 和 get_project 中成功编译的报告省略 log_tail，并显式标记 log_tail_omitted。原始报告、完整日志路径、诊断、固件哈希和状态保留。失败、超时等报告不裁剪。
- get_hardware_info 增加可选 sections，按 profile 顶层字段读取。默认 null 保持完整返回；[]仅保留概要和必要元数据，仍可同时获取例程或共享配置。始终保留生成状态、notes、source_refs、provenance、库存及角色。available_sections 和 omitted_sections 明示范围；缺省字段不能理解为不存在。未知分组报错。
- read_project_file 增加从1计数、包含末行的 start_line/end_line；默认读取全文。返回完整文件哈希、版本、总行数和 partial；局部内容不可用于整文件覆盖。补丁Schema不继承这些读取选项。
- 提示词要求复用同轮未变化资料，首次选型读取完整资料，后续按需补充。没有自动跳过工具执行或依赖可能过期的缓存。
- 运行 summary.tool_payload_characters 按工具统计请求数、参数字符量及返回字符量。这是诊断指标，不是token计数，也不计算内容在后续模型输入中重复出现的倍数；提供方usage仍是token统计依据。

## 已有记录分析

对最近两次运行记录只读分析，较大的内容包括硬件资料/例程、源码读取，以及写操作重复返回的设计。写文件原本就没有回传整份源码；源码仍存在于模型写文件的参数消息中，本阶段没有移除它。

## 后续评估

对多个任务比较实际输入/输出token、缓存命中、调用次数、耗时、交付及失败状态，同时注意是否因为少读资料而增加反复读取。必要时再设计历史工具调用与结果成对压缩，保留本地原始证据、当前版本和可重新读取的位置。不得加入单工程答案模板或特殊验收规则。
