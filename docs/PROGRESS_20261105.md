# 当前进度与下一步：第三个验证子Agent

更新：2026-11-05。本文是当前进度入口；较早的日期化测试报告保留为历史证据。

## 当前已经完成

- 使用LangChain作为Agent核心；ESP-Claw用于学习工具、循环、技能和上下文组织，不是运行依赖。
- 主协调层管理任务、固定阶段委派、项目版本和交付。selection完成选型与兼容性判断；generation完成具体接线、固件、检查、编译和受限的编译修正。
- 元件连接卡关联本地保存的上游Wokwi、驱动API和有来源的指导。工具只读本地资料，不在生成期间临时联网猜参数。
- 工具契约明确board_id自动创建mcu、components只含外设，实例ID和硬件库ID含义不同；错误说明位置和修正动作，失败不保存工程。
- read_hardware默认56,000、最高120,000字符。返回missing_required_refs、next_reads、blockers；生成宿主累计记录stage_usage，不将单次补读complete当成全部资料齐全。
- 已有Wokwi CLI/MCP观测适配，可复用串口、数字引脚、控制、截图等能力；证据能力有边界。pinRead不返回电压，截图依赖模型及现有通用MCP补丁，VCD需合适接线与进一步解析。

尚未完成：verification子Agent、需求驱动的通用功能评估及跨阶段修正闭环。已有evaluate_tests主要报告证据/执行状态和验收缺口，不是完整验收器。当前编译交付平台仍限登记的ESP32-S3仿真基线，不是通用多板卡支持。

## 本轮验证结果

相关86项离线测试通过，新增7项覆盖字段语义、错误后工程不变、较大原文返回、续读批次/预算、损坏来源和累计状态。测试fixture只证明软件机制。

真实模型为deepseek-flash。同一摇杆＋240×240屏幕圆点界面需求，从空工程独立执行两次；不手工修补生成物。宿主顺序调用真实selection/generation，主协调LLM未参与。

### 剩余成本

两次首包主动使用120,000字符上限一次读齐必要资料，再读示例；没有触发必要缺项续读，所以真实模型的next_reads遵循效果仍需后续验证。原来的缺必要资料与重复mcu错误没有复现。

生成末轮仍携带81,277/77,245字符的硬件工具结果；检查、编译、报告三轮合计130,002/125,804 tokens，约占生成阶段41%。非缓存生成输入37,756/32,064，对照37,057；主要减少了缓存历史的重复发送，费用降幅不能按总token降幅直接推断。

已讨论但未实现：硬件设计与固件编写使用不同资料视图，阶段切换只保留需求、接线设计、关键约束和来源；按API/章节读取原文；宿主推进确定性检查/编译路径。按最新安排先推进第三子Agent，不在此检查点继续重写生成流程。

## 下一步：verification子Agent（待实现）

### 职责与输入

验证当前已检查、编译的工程是否满足用户需求，主动设计输入刺激和观察方式，采集证据并解释失败。输入只包含当前需求/约束、项目ID与版本、generation交接、设计和固件证据引用、已有测试计划与反馈。按需读取源码或资料，不继承完整生成对话和全部硬件原文。

测试前把需求分解为可观察条件，记录覆盖项、输入、预期关系、适用依据和观察方法。用户明确改变需求才更新验收条件；不能为了让工程通过而削弱标准。复杂时序、图像、不可观察量要明确支持范围。

### 工具范围

优先复用已有get_project、read_project_file、inspect_simulation、read_simulation_evidence、必要的read_hardware及simulate_project。旧evaluate_tests不能直接当作验收完成；需要设计结构化测试计划、结果与确定性评估接口，名称和Schema在实现时确定。

验证Agent不直接写固件、不重新选型、不烧录。普通修复交回generation；选型/资源冲突交回selection。测试场景或诊断仪器若需要写入，须通过限定的测试工件接口和独立测试版本记录，不能悄悄改变被测固件或电路。

图像需真正传递给支持视觉的模型，不能只在文字中放图片路径；先核对现有模型能力和图片消息通道。数字引脚快照、串口、截图、VCD分别证明不同事实，不能互相替代。能力不足返回证据不足或不支持。

### 输出与退出

拟定VerificationReport，将执行状态和功能结论分开：completed表示流程结束，不自动表示pass。保留逐需求结果、观察值、预期依据、证据引用、覆盖缺口、诊断、修正建议和下一阶段。功能结论至少区分pass、fail、证据不足、不支持，以及工具错误/超时。

通过须有当前修订证据与明确覆盖；失败须给可复核反例；证据不足不能冒充失败或通过。报告绑定源码、电路、固件和项目修订，修改后旧结论失效。宿主需要审查证据身份、覆盖和结论，不能只相信模型说pass。

主协调层决定是否交回generation修正，然后在新修订复测。共享token/时间预算，限定验证与修正次数；相同修订、相同测试、相同结果无进展时停止。取消、异常和阶段退出都必须释放MCP会话，禁止无限循环或死锁。具体阈值先按测试记录制定，不在本次文档更新中新增生产预算。

### 实施顺序

1. 定义验证输入/输出契约、需求到观察条件的表示、工具白名单与退出规则。
2. 独立实现verification执行器，先验证能读取已生成工程、调用观测工具、保存真实证据并如实报告未覆盖项。
3. 用多种器件组合验证正确工程、故意缺陷、证据不足、工具错误、取消与超时；fixture只测软件机制。
4. 接入主协调层的generation→verification交接，检查版本变化后旧证据失效。
5. 实测verification→generation→verification的有限修正链，记录首次/修正后结果、每阶段tokens、缓存、墙钟和模拟时间；不手工修生成物冒充Agent成功。
