## 4. 上下文保留问题：本地回放所得证据

使用真实`message_view.build_view()`对运行事件重建的消息进行离线回放，没有额外API请求。回放用于核对工具正文的投影行为，不是完整HTTP请求抓包或真实token节省对照实验。

1. 第16、17次模型请求前，第一次MCP结果仍有完整正文：20条含文本的记录，其中6条为串口记录。此时Agent读取的是第二次会话的错误文件。
2. 第18次请求前，第一次MCP结果超出最近3组完整工具轮次，被替换为回执；保留操作/状态/证据入口，但观察正文已省略。
3. 第18–20次响应请求重新读取第一次MCP会话的6份响应文件。第16–20次请求总计消耗133,736 tokens；这些调用包含有效错误调查，不能把总量都当成可节省成本。

因此不能说第一次MCP结果从未提供给Agent。已确认的问题是：**仍需用于分析的证据会仅因轮次变旧而失去正文，随后出现重复读取**。改进方向是依任务、未解决问题、版本及证据关系管理上下文；方案见[Context Provider规划](GENERATION_CONTEXT_AND_SKILLS.md)。尚未实现优先级机制，也未测得它能节省多少tokens。

另两个通用改进点是：MCP返回简短的根因摘要同时保留原始异常；明确自动启动及宿主时间/模拟时间的区别。均须作为通用适配器机制处理，不能按本工程日志或固定读数特判。
