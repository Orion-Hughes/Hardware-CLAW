# 资料读取与重复上下文优化记录

日期：2026-10-29（香港时间）。目标是在保持来源、约束和失败证据的前提下，减少Agent反复发送的资料。**机制已实现；本次真实生成验收未通过，没有产出可打开的simulation工程。**

后续记录：用户将工程预算提高至50万后，Agent已生成源码，但仍未完成编译交付，见[50万预算复测](AGENT_500K_RETRY_20261029.md)。下文的设计v1和20万预算结论保留为当时的两次实验结果，不表示最新工程状态。

## 实现内容

1. `get_hardware_info`默认`detail=compact`：去除重复原文路径和完整驱动索引，保留规格、映射、状态、未知项、notes和来源标识。`detail=full`可取完整记录。`sections`仅接受实际返回的字段；无效字段会返回可选字段，不静默忽略。
2. `get_driver_api`默认精简目录，每页12项；正文/检索默认3000字符。`query`对该器件全部登记原文作字面、不区分大小写检索，可结合`reference`缩小范围。片段带原文偏移、行号与SHA256；不是LLM摘要。需要上下文时继续按`reference/offset`读取。
3. 模型可见API目录排除贡献指南、仓库管理文件等；原始文件、许可证和锁文件保持不变。框架、依赖版本及缺失资料状态没有改写成“已支持”。
4. `MessageViewMiddleware`只构建发送给模型的视图。保留最近3组完整工具请求/结果、各技能最近读取的正文页及最近2份不同API读取；较旧的大结果变成带版本、结论、哈希及重读入口的回执。短结果不会因回执变大；错误保留。旧大文件写入参数只在视图中省略，原始日志、工具调用和生成文件不变。
5. 技能目录只注入ID/描述；提示词鼓励将互不依赖的资料查询合并请求，复用本轮已读资料，并在必要依据齐备后进入实现。版本相关读写仍顺序执行。
6. 预算预检按聊天协议中的消息与工具Schema计算UTF-8字节数，再加4096余量并预留输出。排除了不会发送的LangChain用量元数据、追踪信息和重复tool_calls。**这项修正改善本地估算，不会直接降低提供方实际输入。** 仍为保守估计，未换成提供方精确tokenizer，未提高生产预算。

没有新增工程专用模板、技能、固件答案或解析规则；没有额外LLM摘要调用。动态工具组裁剪、跨轮资料读取检查点、通用无进展检测仍未实现。

## 真实Agent测试与成本

组合：ESP32-S3＋库中的电位器＋SG90。需求为旋钮控制0～180°目标角度，每秒报告ADC/目标角度；最终需人工观察舵机动作，串口目标值不能替代动作验收。

两次均绑定`workspace/knob-servo-1793249865-f21282789a09`，没有人工修改生成内容。模型响应元数据为`deepseek-flash`。

|---|---:|---:|---:|
| 模型调用 | 9 | 3 | 12 |
| 工具请求/返回 | 18/18 | 7/7 | 25/25 |

首次测试读取了资料、原始API、技能并保存设计v1。第10次调用前，本地估算输入86,165，而已经计入128,441，因此在200,000总限额前阻断。

续接测试应用了聊天协议估算与短回执改进，测试预算明确缩到**71,559**，把首次消耗计入本次200,000合计额度。续接只要求生成源码与基础检查，计划之后由现有工具直接编译/仿真，不再为固定步骤额外调用模型。它读取工程与资料后，下一次输入估算51,989，加已计入25,835超过71,559，被提前阻断。工具链尚未进入源码写入，因此后续编译、CLI、MCP与导出没有运行。

两次已返回的统计都有对应usage；运行异常终止使当前汇总逻辑将`usage_complete`标为false。这里照实保留，不推断人民币费用或未返回计费。预检拦截的下一次请求没有发送。

续接中的一次参数错误实际来自`get_hardware_info.sections`：模型猜了`pinout/constraints`等不存在的分组，并非`get_driver_api`检索失败。现已改进通用参数说明与错误反馈，并通过离线测试；**这项最后的反馈改动没有再次付费验证。**

## 验收结论与下一步

**可验收的是资料精简、可追溯检索、消息视图和预算机制；不能验收生成工程功能。** 当前只有设计v1，没有固件、编译结果、仿真证据或simulation目录。不能拿旧成功工程代替本次结果。

本次证据说明：缩短工具返回和历史视图有所效果，但尚不足以在现有预算内完成这个组合。查询轮次、固定流程中的模型往返以及保守预算估算仍是问题。续接会读取资料也与当前运行时只保留完整问答、没有恢复上轮工具上下文有关；不能只归因于模型忘记资料。

后续优先研究通用机制：

1. 明确资料阶段完成条件，避免资料齐备后继续收集；保持不同器件相同规则。
2. 考虑由宿主推进无须推理的固定检查/构建/导出步骤，仅把需要诊断的反馈交给模型。
3. 研究可恢复的来源读取记录及按阶段显示工具Schema，减少续接重查与每次重复发送的接口描述。
4. 校准预算估算与真实usage的差距；不能为某个案例放宽额度或把估算当提供方账单。
5. 在明确新的测试预算后，再做从需求到可打开仿真目录的真实验收，并保留失败样本。

以上为后续方向，不表示已经实现。功能验收仍由独立证据和人工观察确认，不由模型宣布通过。
