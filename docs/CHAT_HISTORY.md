# 持续修改与历史会话

网页保留Chainlit原生侧栏：新建聊天、列表、搜索和恢复。默认直接输入需求创建工程；后续反馈绑定同一ProjectService。只有显式/new或/project改变绑定，/query暂时解除绑定进入只读模式。

## 文件与恢复

- `workspace/<project_id>/files/`：同一工程持续编辑的位置。
- `workspace/<project_id>/.hwclaw/revisions/`：不可变历史修订。
- `workspace/<project_id>/exports/vNNNNNN/simulation/`：对应版本交付快照，VS Code需打开最新回复提供的路径，不自动覆盖旧目录。
- `workspace/.chat/history.sqlite3`：本地SQLite，保存聊天、工具步骤、最近三轮完整问答和绑定project_id。正式运行数据，不放temp；已gitignore。
- `workspace/.chat/assets/`：恢复历史所需的附件副本。通过带会话认证的下载接口读取。
- `.secrets/chainlit-auth-secret.txt`：本地会话签名密钥，运行时生成，不给LLM、不进生成包。

恢复时按thread_id读取独立状态，再通过ProjectService.open打开原工程；找不到工程时明确提示并进入查询模式，绝不静默创建替代工程。框架自己的metadata回写不覆盖工程绑定。完整历史用于UI，只有最近三轮已完成问答进入模型上下文。

## 反馈修改

提示词要求先读取当前设计/文件，按反馈最小修改。咨询保持只读。只要运行前后工程版本变化，宿主就要求当前修订交付，并独立判断验证状态，不能沿用旧版本的成功。预算耗尽不删除工作；可按现有规则打包已经检查编译的文件。

## 边界

仅本机单用户服务（启动脚本绑定127.0.0.1）。采用本地自动身份以启用Chainlit历史，不是互联网身份认证；不能直接改为公网监听。侧栏删除聊天只删除聊天记录，不删除生成工程；附件副本暂不自动清理。

更新前未持久化的旧聊天无法自动补回。旧工程仍可用/project恢复。多个聊天可以显式打开同一工程，文件写入仍使用已有版本冲突检查；不提供跨聊天长任务队列。切换会话不是后台并行运行任务的承诺。

## 验证

离线覆盖存储重新打开、分页/归属、附件、聊天删除保留项目、A→B→A工程和上下文恢复，以及反馈修改后的交付检查。实际浏览器使用/project绑定两个现有工程，确认侧栏出现两条历史并能切换；不调用LLM、不修改生成工程。
