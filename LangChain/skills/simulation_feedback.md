# Wokwi仿真、评估与有限修正

vscode默认交付含真实固件的simulation文件夹；导出前运行simulate_project并evaluate_tests。不能把能启动等同功能通过。

当前固定场景只覆盖单个DHT22的串口反馈，刺激24°C/40%→30°C/65%→24°C/40%并再次读取恢复值。测试定义在宿主，不接受Agent自写的预期或YAML。输出协议为 `Temperature: 24.0 C | Humidity: 40.0 %`，保留一位小数，建议printf使用\r\n结尾。数值必须来自实际传感器读取，禁止常量假数据或识别测试后输出预期。

流程：check_project_files→compile_project→simulate_project→evaluate_tests；失败先read_project_file检查相关代码，对照硬件资料、serial_tail和findings定位问题。改动后必须重新检查编译仿真。工具不开放任意Shell、密钥、测试文件改写或全磁盘读写。

每轮最多3次仿真（初次+两次修正），每次模拟25秒、墙钟90秒，总任务900秒。同一固件/电路/测试返回已有证据，不能通过重复运行假装修复。同错误无进展则停止。失败后禁止仅清理变量、格式、注释再重试；修复必须解释它如何针对本次失败证据。网络/凭据/工具错误不归因于硬件，unsupported明确说明缺失场景。即使fail也可以导出用于人工查看，但必须如实报告。预算耗尽时宿主会尝试打包现有已编译工程，不修源码、不改变失败判定。

已知兼容性证据（2026-10-27本地对照，不是全平台结论）：当前ESP32-S3/espressif32@6.12.0/原版DHTesp1.19可编译但在Wokwi中可能TIMEOUT。用户参考工程采用开漏释放总线的本地DHTesp修订及10kΩ上拉通过动态场景；换回原版库失败。该修订尚未登记成Agent可安装的driver variant。遇到相同问题应报告驱动兼容性疑点与资源缺口，不能声称已装上修订，不能随意更换GPIO或伪造读数掩盖失败。没有资料依据的底层驱动修复不在本轮工具能力范围内。

evaluate_tests只判断DHT22串口场景，不覆盖显示屏、其他外设、完整业务、精确2秒采样或真机电气安全。问题诊断由LLM解释，pass/fail由Python根据实际证据判定。TIMEOUT本身不能唯一证明驱动缺陷、握手错位或电气故障，必须把候选原因与实测事实分开；本地已知组合不应外推到全部DHT22仿真。
