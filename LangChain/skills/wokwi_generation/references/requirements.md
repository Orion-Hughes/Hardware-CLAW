# 需求与可行性

提取用户需要的输入、输出、触发条件、采样/响应/刷新时间、异常行为和交付范围。区分明确要求与实现假设。

- 从现有工具和本地资料判断是否能实现；缺少资料不等于硬件一定不支持。
- 影响硬件选择、关键行为或外部协议的缺失信息需要澄清；普通显示格式等可合理默认并记录，不逐项追问。
- 模拟器不支持的能力与真实硬件缺失分开说明。可完成一部分时明确范围，不用其他输出冒充要求。
- 简述行为决策即可，保存到现有design/assumptions和README；不为简单工程额外生成设计报告。
- 需求描述不是验收证据。将未来需要观察的现象写清，但不自行添加项目专用的通过判断程序。
