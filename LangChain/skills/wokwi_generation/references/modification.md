# 修改已有工程

1. 读取最新工程状态和相关文件，以工具返回为准；Context摘要只帮助定位。
2. 确认改变的是行为、接口、引脚、依赖还是交付方式。读取受影响驱动API与必要源码，不重读所有资料。
3. 列出修改会影响的文件。优先最小必要改动，但需要重构时说明通用原因。
4. 依次保存变更，每次使用最新版本。设计改变后同步连线图、依赖和引脚声明；不可用局部读取内容覆盖整个文件。
5. 重新运行分阶段检查。宿主确认输入和环境一致时可复用编译记录；电路变化需要当前电路的仿真证据。报告标明cached/reused_from_version；模型不能自行把旧结果当作新版本通过证据。
6. 不手工改旧导出目录；用当前工程重新导出，保留历史证据。不能为了消除报错而删掉用户要求或伪造输入。
